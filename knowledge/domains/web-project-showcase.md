| ID | Purpose | Default duration | Evidence |

Optional cover image for each, clean text-free source/sidecar if feasible. Default captions Ukrainian; provide EN text/SRT for reuse, English render optional on request. Silent-first (understandable without music or narration); music must be licensed or original; voice optional, never fake client voice. ## 1. Plan once
Write evidence.json, shots.md, claims.md, and assets map. Each beat: purpose, real state/illustration, action, outcome, duration, evidence ID, framing, caption, redaction. Lead with payoff in first 2 seconds; show concrete improvements, not generic marketing fluff. No invented percentages, time saved, clients, or capabilities. Reuse palette and typography from actual product. No long intro/logo animation. Choose a single CTA appropriate to audience (e.g. order print or contact developer), truthful and neutral.
Use explicit scope in user's brief to avoid redundant interview; if material is missing, deliver independently verifiable parts. Canonical approval gate applies to final story/audio; if owner expressly delegates drafting, render private review candidates without waiting on an extra questionnaire, never mark final approved without review.

## 2. Capture once, render in parallel
Capture baseline/current matched browser states with same viewport, fonts, theme, inputs, data (where possible), scroll and readiness. Capture desktop + mobile. Record a dry run, then actual flow: real browser at human pace, intentional pauses, visible cursor/touch indicators, no skipped critical states, explicit speed-up for wait. Use authorized demo data. Capture action marks and preserve raw video. Use local SSD; no concurrent heavy renders on NAS.
- Real capture: choose already available Playwright/OS capture or demo-video-skills; Chrome native capture optional if compatible. Real cursor overlay follows actual interaction, never invents result. Save browser take(s) and marks. If Chrome capture outputs AV1, transcode delivery to H.264. For macOS Docker recorder only if already available and approved; no heavy new infrastructure.
- Teaser: use Stageshow's React/plain CSS kit and actual product tokens, screenshot-informed states; separate video workspace, never convert app to React. 3–5 beats, result hold, clear poster, inspect frames and upstream rehearsal gate. Use Remotion for final framing/export if already suitable, or capture rendered demo and encode. Never use simulated UI as proof. If Stageshow unavailable, create equivalent honest animated graphics with installed tools.
- Weekly case study: matched before/after wipe or split, real zooms, 2–4 proven improvements, customer value, short CTA. If no authentic before evidence, use labeled "current state / verified changes" instead of fake before. No claims without evidence.
Parallelize research/asset prep and independent editing only after evidence locked. One agent coordinates story/branding. Use cheap models for inventory and mechanical rendering, stronger review only as needed.

## 3. Deliver
Suggested private output folder: outside site repo and skill repo, e.g. `Work/Video Montage/projects/<slug>/deliverables/<YYYY-MM-DD>/` after verifying destination; render on SSD then copy outputs. Keep source media read-only. Deliver 6 MP4s (3 films × 2 aspects), 3 cover images if feasible, captions/text, shot/evidence manifest, editable source/timeline, QC report and brief client update. No raw secrets in evidence files. Do not commit media or customer evidence. A missing variant is PARTIAL, not Done.
QC: playback each master full length, verify readability on phone, first/last frame, no black gaps, cut continuity, cursor matches state, sound/rights, no leaking private data, no unverified claims; ffprobe resolution/codec/duration/fps; visual contact sheet and sample audio when used. Record PASS/FAIL/BLOCKED/NOT RUN per output. Do not claim real browser capture or rendered film without actual files. Ship private review candidates first; publication requires owner approval.
